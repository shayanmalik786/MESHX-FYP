MESHX – ADAPTIVE OFF-GRID COMMUNICATION SYSTEM USING LoRa
HARDWARE PROCUREMENT LIST + ALTERNATIVES
===============================================================

Project basis
-------------
- 5–6 physical LoRa mesh nodes
- ESP32-S3 + SX1262 as the primary node platform
- SX1262 connected to ESP32-S3 over SPI
- Li-ion/LiPo battery with charging/protection
- BLE interface to Android phone
- Custom mesh networking protocol
- Alternatives mentioned in the proposal: LLCC68 / SX1278
- Optional/stretch items: GPS, OLED, solar charging
- Development tools: Arduino / ESP-IDF, Android Studio, Python, Git/GitHub

===============================================================
A. CORE NODE HARDWARE
===============================================================

1. ESP32-S3 DEVELOPMENT BOARD
---------------------------------------------------------------
Primary:
- ESP32-S3-DevKitC-1
- Recommended variant: ESP32-S3-WROOM-1-N8R8
- Flash: 8 MB
- PSRAM: 8 MB
- Logic: 3.3 V
- Interfaces needed: SPI, UART, GPIO, BLE
- Bluetooth: BLE 5-class support
- USB for programming/debugging
- Quantity: 7 (6 required + 1 spare)

Alternatives:
A) ESP32-S3-WROOM-1 development board with equivalent 8 MB Flash /
   8 MB PSRAM configuration
B) LilyGO T3-S3 / similar ESP32-S3 LoRa development board
   (only if using an integrated SX1262 version)

Recommendation:
Use separate ESP32-S3 DevKitC-1 boards for the first prototype because
they make SPI debugging and the hardware architecture easier to understand.

---------------------------------------------------------------

2. LoRa TRANSCEIVER
---------------------------------------------------------------
Primary:
- Semtech SX1262 based LoRa module
- SPI interface exposed
- Sub-GHz operation
- 3.3 V logic
- Up to approximately +22 dBm TX capability depending on module/configuration
- Must support the exact RF band selected for Pakistan operation
- Quantity: 7 (6 required + 1 spare)

Alternatives:
A) LLCC68 based LoRa module
   - Lower-cost SX126x-family alternative
   - Verify exact frequency, power and library support before purchase

B) SX1278 based LoRa module
   - Older, mature and often cheaper
   - Verify exact frequency/regulatory compatibility
   - Verify library and driver support for the chosen board

C) SX1276 based LoRa module
   - Mature LoRa transceiver family
   - Often widely available
   - Verify frequency variant and integration effort

IMPORTANT:
Do not order a UART-only LoRa module. The accepted proposal requires
ESP32-S3 <-> SX1262 communication over SPI.
The exact RF frequency/module variant must be finalized before ordering.

---------------------------------------------------------------

3. LoRa ANTENNA
---------------------------------------------------------------
Primary:
- Antenna matched to the final selected LoRa operating band
- 50 ohm impedance
- Omnidirectional
- Approximately 2–5 dBi gain for initial testing
- Vertical polarization
- Correct connector for the selected LoRa module
- Quantity: 8 (6 required + 2 spares)

Alternatives:
A) Flexible whip antenna
B) Rubber-duck antenna
C) Quarter-wave antenna designed for the selected frequency

Do NOT mix antenna frequency bands.
Antenna must match the actual RF operating frequency.

---------------------------------------------------------------

4. BATTERY
---------------------------------------------------------------
Primary:
- 1-cell Li-ion or LiPo
- Nominal voltage: 3.7 V
- Fully charged voltage: approximately 4.2 V
- Capacity: approximately 3000–5000 mAh
- Recommended starting choice: approximately 4000 mAh
- Protected cell preferred
- Quantity: 7

Alternatives:
A) 3000 mAh protected 1S Li-ion/LiPo
B) 5000 mAh protected 1S Li-ion/LiPo

Choose battery capacity after measuring actual node power consumption.

---------------------------------------------------------------

5. BATTERY CHARGER + PROTECTION
---------------------------------------------------------------
Primary:
- 1S Li-ion/LiPo charging board
- 5 V input
- Approximately 1 A charging capability
- Overcharge protection
- Over-discharge protection
- Over-current/short-circuit protection
- Quantity: 7

Alternative:
- Any reputable 1S power-management/charger board with integrated
  protection and suitable charging current.

Important:
A charger/protection board is NOT automatically a 3.3 V regulator.

---------------------------------------------------------------

6. 3.3 V REGULATOR / POWER MANAGEMENT
---------------------------------------------------------------
Primary:
- Stable 3.3 V regulated output
- At least 1 A continuous capability
- Preferably 1.5–2 A peak capability
- Suitable for ESP32-S3 + SX1262 transient current
- Quantity: 7

Alternatives:
A) Low-IQ 3.3 V buck-boost regulator
B) Suitable 3.3 V buck regulator where the voltage range permits
C) Appropriate 3.3 V LDO for prototype testing if heat/current
   requirements are acceptable

Do not connect a raw Li-ion battery directly to a 3.3 V-only rail.

---------------------------------------------------------------

7. POWER SWITCH
---------------------------------------------------------------
- Small SPST ON/OFF switch
- Quantity: 7

Alternative:
- Slide switch / rocker switch with adequate current rating.

---------------------------------------------------------------

8. BATTERY CONNECTORS
---------------------------------------------------------------
Primary:
- JST-PH 2.0 mm or connector matching the selected battery
- Quantity: 10

Alternatives:
- JST-XH or another locking connector only if it matches the chosen
  battery/PCB wiring.

===============================================================
E. RECOMMENDED PROCUREMENT STRATEGY
===============================================================

PHASE 1 – BUY FIRST (2-NODE PROTOTYPE)
---------------------------------------------------------------
- ESP32-S3 DevKitC-1 x2
- SX1262 SPI LoRa module x2
- Correct-band LoRa antenna x2
- 3.7 V battery x2
- Charger/protection x2
- 3.3 V regulator/power solution x2
- Power switch x2
- Breadboard x2
- Jumper wires
- Multimeter
- Logic analyzer
- USB data cables

Goal:
ESP32-S3 -> SPI -> SX1262 -> LoRa -> SX1262 -> SPI -> ESP32-S3

First successful message:
NODE_A: HELLO
NODE_B: HELLO ACK

Then log:
- RSSI
- SNR
- packet success/failure
- latency

PHASE 2 – REPLICATE
---------------------------------------------------------------
After the 2-node link is stable:
- Purchase/assemble remaining 4 nodes
- Keep 1 spare ESP32-S3 and 1 spare LoRa module

PHASE 3 – MESH
---------------------------------------------------------------
Then implement:
- Node IDs
- Packet format
- Neighbor discovery
- Forwarding
- TTL
- Duplicate detection
- ACK
- Retransmission
- Store-and-forward
- Route recovery

PHASE 4 – ADAPTIVE ROUTING
---------------------------------------------------------------
Collect:
- RSSI
- SNR
- Packet-loss rate / PDR
- Battery level

Then implement:
- Link-quality normalization
- Composite routing score
- Adaptive path selection

Compare:
- Flooding
- Shortest-hop
- Adaptive routing

PHASE 5 – SECURITY + ANDROID
---------------------------------------------------------------
Security:
- AES-256-GCM
- Node authentication / signed identities
- Message integrity
- Replay protection as part of the detailed protocol design

Android:
- BLE connection
- Send/receive message
- Connected-node information
- RSSI
- Hop count
- Delivery status
- Network topology
