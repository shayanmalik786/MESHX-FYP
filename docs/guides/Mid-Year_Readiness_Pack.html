5.2 Radio start-up notes

  • Use the RadioLib library. Typical first configuration: SF7, bandwidth 125 kHz, coding rate 4/5, private sync word 0x12 (avoids LoRaWAN traffic), preamble 8, CRC on.

  • The most common reason a new SX1262 module does not initialise is the TCXO (controlled through DIO3) or the RF switch (DIO2 or RXEN/TXEN). Read the module datasheet for both.

  • Bench testing: keep nodes at least 1 m apart and use low power (2–10 dBm). Two radios touching at full power can saturate the receiver.

  • Use channel activity detection (CAD) plus a random backoff before every transmission.

8. Research notes

8.1 How LoRa works

LoRa uses chirp spread spectrum. Three settings control it: spreading factor SF (7 to 12), bandwidth BW (125, 250 or 500 kHz) and coding rate CR (4/5 to 4/8). A higher SF gives more range but a much longer transmission time and a lower data rate. Symbol time is 2^SF / BW, and the Semtech airtime formula adds preamble and payload symbols.

Airtime at 125 kHz, CR 4/5, 8-symbol preamble, explicit header, CRC on (calculated with the Semtech formula):

SF 20-byte payload 50-byte payload 100-byte payload Bit rate Minimum SNR
7 57 ms 98 ms 174 ms about 5.5 kbps -7.5 dB
8 103 ms 175 ms 308 ms about 3.1 kbps -10 dB
9 185 ms 329 ms 554 ms about 1.8 kbps -12.5 dB
10 371 ms 616 ms 1026 ms about 1.0 kbps -15 dB
11 741 ms 1315 ms 2216 ms about 0.54 kbps -17.5 dB
12 1319 ms 2302 ms 3940 ms about 0.29 kbps -20 dB

Receiver sensitivity is roughly -123 dBm (SF7) to -137 dBm (SF12) at 125 kHz for SX127x-class chips; the SX1262 is slightly better (see its datasheet). Every hop re-sends the whole packet, so end-to-end delay is at least hops x (airtime + backoff + processing). Four hops at SF9 with 50 bytes is already over 1.3 s.

8.2 Link budget and forcing multi-hop on campus

Received power = transmit power + antenna gains - path loss. Free-space path loss in dB is 32.44 + 20 log10(distance in km) + 20 log10(frequency in MHz).

Distance 433 MHz 868 MHz
100 m 65 dB 71 dB
500 m 79 dB 85 dB
1 km 85 dB 91 dB
2 km 91 dB 97 dB
5 km 99 dB 105 dB

Real campus paths are worse than free space: model them with a log-distance exponent of about 2.7–3.5 plus shadowing from buildings and trees. With nodes 100–300 m apart, SF7–SF9 is enough. A small campus tends to make every node hear every other node, which would remove the multi-hop behaviour you want to show. To force multi-hop: lower transmit power (for example 2–10 dBm), place nodes behind buildings, and check each link's RSSI to confirm that non-neighbours cannot hear each other.

8.3 Channel access and duty cycle

LoRa has no built-in collision avoidance (basic ALOHA). Use channel activity detection and a random backoff before sending. Regions often limit duty cycle (in the EU 868 MHz band, 1 % is a common limit); the limit for Pakistan must be confirmed. As a design budget, assume 1 %: with 330 ms packets that is about one packet per 33 s per node. Flooding multiplies transmissions, so airtime used per delivered message is a key result for comparing flooding, shortest-hop and adaptive routing.

8.4 Mesh routing background

  • Flooding: every node rebroadcasts once. Simple and robust, but wastes airtime.

  • Managed flooding (Meshtastic): a hop limit, suppression when a node hears another node already rebroadcasting, and a rebroadcast delay that depends on SNR so distant nodes go first. The documentation gives a default hop limit of 3 and a maximum of 7. Your proposal uses Meshtastic only as a design reference.

  • Proactive, reactive and link-state protocols (DSDV, AODV, OLSR): maintain routes with tables; AODV-style and RSSI-based variants have been tried on LoRa.

  • ETX: expected number of transmissions on a link, 1 / (forward delivery x reverse delivery); the classic delivery-based metric.

  • Opportunistic routing: several candidate relays per hop, as in OppLoRa.

  • Energy-aware routing: includes battery state in route choice; this is the closest idea to your battery term.

MeshX takes a custom link-state approach with a composite score from RSSI, SNR, loss and battery.

8.5 Adaptive link-quality design (proposal)

Measurements per neighbour, from HELLO beacons: RSSI and SNR smoothed with an exponential moving average (alpha about 0.2); loss rate from gaps in the beacon sequence number over the last 10–20 beacons; battery percentage carried inside the beacon.

Normalisation (each value 0 to 1):

  • R = clamp((RSSI + 120) / 60, 0, 1)

  • N = clamp((SNR - SNR_min(SF)) / 15, 0, 1), where SNR_min(SF) = -7.5 - 2.5 x (SF - 7)

  • Q = 1 - loss

  • B = battery percent / 100

Link score: S = wR x R + wN x N + wQ x Q + wB x B, weights summing to 1. Start with 0.35, 0.25, 0.25, 0.15 (the same defaults as the interactive schematic) and tune in February–March by switching each weight off in turn (ablation).

Path choice: link cost c = -ln(max(S, 0.05)) + 0.1, where 0.1 is a small per-hop penalty. Each node gossips its neighbour scores in beacons, builds the graph and runs Dijkstra. For asymmetric links use the lower of the two directions.

Avoid route flapping: change the route only if the new path is at least 20 % cheaper for 3 consecutive beacon intervals. Declare a neighbour dead after 3–4 missed beacons. Add a penalty for next hops below 20 % battery rather than excluding them.

8.6 Protocol design notes

  • Header: destination 2 B, source 2 B, packet ID 2 B, TTL 1 B, type 1 B = 8 bytes. With nonce 12 B and authentication tag 16 B the overhead is 36 bytes, leaving about 219 bytes for text in a 255-byte LoRa frame.

  • Packet types: DATA, ACK, HELLO, link-state update.

  • ACKs: hop-by-hop ACK for fast recovery and an optional end-to-end ACK for delivery status in the app. Retransmission timeout is about 2 x data airtime + ACK airtime + jitter, with at most 3 retries.

  • Duplicate cache: ring buffer of the last 32–64 (source, packet ID) pairs.

  • Discovery: HELLO beacons with TTL 1 for neighbours; link-state updates with a larger TTL.

  • BLE: a Nordic-UART-style service: one write characteristic from the phone, one notify characteristic to the phone, larger MTU, chunking for long text.

8.7 Security design notes

  • Encryption: AES-256-GCM through mbedTLS (it uses hardware acceleration on the ESP32). The 96-bit nonce must never repeat under one key: build it from node ID plus a counter stored in flash.

  • Replay protection: keep the highest counter seen per source and reject older ones.

  • Identity: a shared network key means any holder can forge any node, so each node also signs its HELLO beacons with its own key pair (for example Ed25519). A 64-byte signature is too large for every data packet, so sign beacons only.

  • Honest limits to state in the report: key provisioning is manual; no key rotation; flash encryption and secure boot are out of scope.

8.8 Evaluation methodology

Metric How to measure
Packet Delivery Ratio Delivered divided by sent, per flow
End-to-end delay No clock sync between nodes, so use round-trip time of the end-to-end ACK divided by 2
Throughput Delivered payload bytes divided by time
Energy Voltage x current over time from the meter, reported as mAh per delivered message
Route recovery time Time from switching off an intermediate node to the first successful delivery by another path

Test matrix: topologies (direct, 2-hop, 3-hop, 4+ hops) x routing modes (flooding, shortest-hop, adaptive), at least 30 messages per run, at least 3 repeats, payloads of 20, 50 and 100 bytes. Use the same physical topology for all three modes. Node-failure test: switch off a relay in the middle of a 50-message run. Interference test: add another LoRa transmitter on the same channel or raise traffic. Report mean and standard deviation or a 95 % confidence interval, and log everything.

8.9 Energy and battery-life estimate (approximate, replace with measurements)

Datasheet-class values: SX1262 receive about 5 mA, transmit at +22 dBm about 100–120 mA, sleep far below 1 uA; ESP32-S3 with BLE active about 60–120 mA average with higher peaks. An always-on node therefore draws about 100 mA: a 4000 mAh battery gives about 40 hours ideal, about 30–35 hours after regulator losses. Duty-cycled receive and light sleep are stretch goals.
