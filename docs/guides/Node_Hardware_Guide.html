One LoRa mesh node, explained part by part: how the ESP32-S3 talks to the SX1262 radio, where every wire goes on the breadboard, how the battery powers it, and every component you need to buy, with alternatives and Pakistan prices from your price list.

What MeshX does

5–6 battery nodes placed around campus pass text messages hop by hop over LoRa, with no cellular, Wi-Fi or internet. A phone talks to its nearest node over BLE. Routing picks the path with the best measured link quality (RSSI, SNR, packet loss, battery) instead of the fewest hops. That adaptive routing is your original contribution. Tap any block below.

Rules for this board

Never connect J1 pin 21 (5V0) to the radio. SX1262 is a 3.3 V part and 5 V can kill it.
  • Pins to avoid: GPIO3 and GPIO46 (J1 pins 13, 14) are strapping pins that set boot mode. GPIO35–37 are used by the octal PSRAM on N8R8/N16R8. GPIO19/20 are the native USB.
  • Module pin order differs from this drawing. Match by the names printed on your module (NSS, SCK, BUSY…), never by position.
  • RXEN/TXEN exist on Ebyte E22 and Waveshare Core1262. Modules without them switch the antenna with DIO2; skip those two grey wires and leave setRfSwitchPins commented.
  • Battery sense on GPIO9 is my addition, not in your list. Your routing score needs battery %, and this two-resistor divider is how the node measures it.
  • Onboard RGB LED is GPIO48 on DevKitC-1 v1.0 and GPIO38 on v1.1. Check the silkscreen version before using it as a status light.
  • Pin order follows the Espressif DevKitC-1 datasheet. Check once against the GPIO numbers printed on your board.

Assembly order

  1. Seat the ESP32: J1 in row c, J3 in row j, pin 22 (G) in column 8. Rows a and b above J1 stay free.
  2. Check your rail markings. If the rail is split in the middle, bridge both halves with a short jumper.
  3. Rail wires: column 8 row a → − rail (black). Column 29 row a → + rail (red).
  4. Capacitors across the rails at columns 40–42: 100 µF striped leg on −, and the 100 nF either way.
  5. Battery-sense divider: R1 100 kΩ from column 44 to column 47 (row c), R2 100 kΩ from column 47 (row b) to − rail. Brown jumper from column 47 row a to column 15 row a (GPIO9).
  6. Nine M-F signal jumpers: male end in the column, female end on the module pin (see column map).
  7. Module power: two M-F jumpers from the + and − rails (columns 45, 46) to module 3V3 and GND.
  8. Screw the antenna on before any power. Transmitting without an antenna can damage the SX1262.
  9. Multimeter continuity between + and − rails. A beep means a short: fix before powering.
  10. First power from the laptop USB only. Battery path comes after the radio test passes.
Do not connect laptop USB and the battery regulator at the same time. Both would drive the 3V3 rail and fight each other. Switch the battery off while flashing.

Power path

USB-C charges the cell through the TP4056. The protected output goes through the switch to a buck-boost that makes a steady 3.3 V from a battery that swings 4.2 V → 3.0 V. Tap any part.

Why a buck-boost?

A Li-ion cell sits above 3.3 V when full and below it near empty. A buck-only regulator stops working once the cell drops near 3.6 V, and an LDO like AMS1117 needs about 4.4 V in. A buck-boost keeps 3.3 V across the whole discharge.

Battery % for the routing score

The divider halves the battery voltage so it fits the ESP32 ADC (4.2 V → 2.1 V). Two 100 kΩ resistors draw only about 21 µA.

battery.cpp
float batteryVolts() {
  uint32_t mv = 0;
  for (int i = 0; i < 16; i++) mv += analogReadMilliVolts(9); // GPIO9
  return (mv / 16.0f) * 2.0f / 1000.0f;   // x2 undoes the divider
}

int batteryPercent() {                      // simple linear map
  float v = batteryVolts();
  return constrain((int)((v - 3.30f) / (4.20f - 3.30f) * 100), 0, 100);
}
A TP4056 board is a charger plus protection only. It is not a 3.3 V regulator. Never wire the raw cell straight to the 3V3 rail.

Test 1: does the radio answer?

#include <RadioLib.h>
#define NSS 10
#define SCK 12
#define MOSI 11
#define MISO 13
#define RST 5
#define BUSY 4
#define DIO1 8
SX1262 radio = new Module(NSS, DIO1, RST, BUSY);

void setup() {
  Serial.begin(115200);
  SPI.begin(SCK, MISO, MOSI, NSS);
  // freq MHz, bw kHz, SF, CR 4/5, private sync word,
  // power dBm, preamble, TCXO volts
  int s = radio.begin(868.0, 125.0, 7, 5, 0x12, 10, 8, 1.8);
  Serial.println(s);   // 0 means the radio responded
  // radio.setRfSwitchPins(6, 7); // RXEN, TXEN if your module has them
}
void loop() {}

0 on the serial monitor means wiring and radio are fine. Set your band first (868.0 or 433.0). Error −2 (chip not found) usually means wiring; then try TCXO 0 instead of 1.8 if your module uses a crystal.

Test 2: HELLO / HELLO ACK

// same #defines and radio object as Test 1
const bool IS_NODE_A = true;      // false on Node B
volatile bool flag = false;
void IRAM_ATTR onDio1() { flag = true; }

void send(const char* m) {
  radio.transmit(m);
  flag = false;                    // ignore the TX-done interrupt
  radio.startReceive();
}
void setup() {
  Serial.begin(115200);
  SPI.begin(SCK, MISO, MOSI, NSS);
  Serial.println(radio.begin(868.0, 125.0, 7, 5, 0x12, 10, 8, 1.8));
  radio.setDio1Action(onDio1);
  radio.startReceive();
}
unsigned long last = 0;
void loop() {
  if (IS_NODE_A && millis() - last > 5000) {
    last = millis(); send("NODE_A: HELLO");
  }
  if (flag) {
    flag = false;
    String msg;
    if (radio.readData(msg) == RADIOLIB_ERR_NONE) {
      Serial.printf("RX %s | RSSI %.1f dBm | SNR %.1f dB\n",
        msg.c_str(), radio.getRSSI(), radio.getSNR());
      if (!IS_NODE_A) send("NODE_B: HELLO ACK");
      else radio.startReceive();
    } else radio.startReceive();
  }
}

Log RSSI, SNR, success/failure and latency from this test. That data is the start of your link-quality dataset.

Troubleshooting

SymptomLikely causeFix
begin() returns −2SPI wiring or BUSY/RESET wrongRecheck NSS/SCK/MOSI/MISO by printed names. Probe SCK and NSS with the logic analyzer.
begin() returns −707 or TCXO errorTCXO voltage mismatchSet the last argument to 0 (crystal) or the voltage from the module datasheet.
Board not seen by laptopCharge-only cable, or wrong USB portUse a data cable on the port marked UART. Hold BOOT, tap RST to force download mode.
Random resets when transmitting3V3 sags on TX current spikeAdd the 100 µF + 100 nF at the module, shorten power wires, use a ≥1 A regulator.
Sends fine, never receivesRF switch not drivenEnable setRfSwitchPins(6,7) on E22/Core1262, or DIO2 control on others.
Very short rangeAntenna band mismatch or loose u.FLAntenna must match the band (868 vs 433). Reseat the pigtail.
Two nodes 30 cm apart lose packetsReceiver overload at short rangeKeep 10 dBm and at least 1 m between nodes when testing.
